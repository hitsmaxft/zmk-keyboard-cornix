01 · Overview

Know each role before you build.

Cornix can run as a conventional two-part ZMK split or with a USB dongle acting as the central. Board names describe the role; shields add dongle, display, or RGB behavior.

!
Zephyr 4.1 requires qualified board targets.

Use the board//zmk names below. An unqualified nice!nano can select the wrong settings backend and lose its Bluetooth identity after reboot.

Direct split · central

cornix_left//zmk

The left half scans its matrix, connects to the host, and receives split input from the right half.

Split · peripheral

cornix_right//zmk

The right half provides its matrix and encoder events to the selected central.

Dongle mode · peripheral

cornix_ph_left//zmk

Use this left-half role when a separate USB dongle becomes the split central.

Optional indicators

Visible state without permanent drain.

The cornix_indicator shield drives two RGB LEDs on each half for battery and split status. Version 3.0.0 defaults to brightness 64 and switches the WS2812 rail off one second after the final transient indication. A deliberately lit LED still uses extra power.

Existing configuration

  1. Merge the manifest
  2. Choose targets
  3. Reset and flash
  4. Recover if needed

Step 1

Merge the Cornix module into config/west.yml

Keep one copy of each remote and project. Pin Cornix to v3.0.0 for a reproducible stable setup; switch to main only when you intentionally follow development.

manifest:
  remotes:
    - name: zmkfirmware
      url-base: https://github.com/zmkfirmware
    - name: cornix-shield
      url-base: https://github.com/hitsmaxft

  projects:
    - name: zmk
      remote: zmkfirmware
      revision: main
      import: app/west.yml
    - name: zmk-keyboard-cornix
      remote: cornix-shield
      revision: v3.0.0

  self:
    path: config
west update

Step 2

Build a conventional two-part split

include:
  - board: cornix_left//zmk
    artifact-name: cornix_left

  - board: cornix_right//zmk
    artifact-name: cornix_right

  - board: cornix_right//zmk
    shield: settings_reset
    snippet: nrf52840-nosd
    artifact-name: cornix_reset

For RGB, add zmk-rgbled-widget to the manifest and set shield: cornix_indicator on the half being built. This is an opt-in, not part of the default release package.

Step 3

Clear old state, then flash matching roles

  1. Put each half into UF2 bootloader mode, usually by double-tapping reset.
  2. Flash cornix_reset.uf2 to both halves when migrating old settings or split bonds.
  3. Flash the matching left and right UF2 files.
  4. Reset or power-cycle both halves together, then pair again.

Step 4

Respect the no-SoftDevice layout

Cornix v2.3 and later use the no-SoftDevice layout by default. If a board no longer enters the expected firmware or you are moving between stock RMK and ZMK layouts, stop and follow the repository's bootloader recovery guide before repeatedly flashing unrelated UF2 files.

03 · Dongle integration

One central. Two quiet peripherals.

In dongle mode the USB receiver owns the host endpoint. Both keyboard halves become split peripherals, so left-half firmware must change from cornix_left//zmk to cornix_ph_left//zmk.

Required

cornix_dongle_adapter

Provides the matrix/split role expected by a Cornix dongle build. The spelling is adapter, not the older adaptor typo.

Display, when needed

cornix_dongle_eyelash + dongle_display

Add the eyelash shield only when the dongle board does not already provide zephyr,display. dongle_display supplies the widgets. The separate legacy dongle_screen path is not the supported Zephyr 4.1 choice here.

Build matrix

Standard dongle composition

include:
  - board: nice_nano//zmk
    shield: cornix_dongle_adapter cornix_dongle_eyelash dongle_display
    snippet: studio-rpc-usb-uart nrf52840-nosd
    artifact-name: cornix_dongle_nosd

  - board: cornix_ph_left//zmk
    artifact-name: cornix_left_for_dongle_nosd

  - board: cornix_right//zmk
    artifact-name: cornix_right_nosd

  - board: nice_nano//zmk
    shield: settings_reset
    snippet: studio-rpc-usb-uart nrf52840-nosd
    artifact-name: reset_nicenano_nosd

Add the current zmk-dongle-display module to your west manifest when using dongle_display. If your hardware already defines zephyr,display, omit cornix_dongle_eyelash and substitute the display shield that matches that hardware.

Persistence gate

A successful compile is not enough.

Inspect the final dongle .config. The qualified nice!nano target must preserve identities and split bonds through NVS:

CONFIG_BOARD_TARGET="nice_nano@2.0.0/nrf52840/zmk"
CONFIG_NVS=y
CONFIG_SETTINGS_NVS=y
# CONFIG_SETTINGS_NONE=y must be absent

If you see No ID address, settings-save errors, SMP failures, or a new Bluetooth identity after every reboot, verify the board qualifier and settings backend before debugging RF behavior.

Advanced RPC extensions

Keep relay features on the same contract.

When enabling DYA Settings RPC or Battery History propagation, the dongle and both peripherals must expose the same split relay contract. A missing relay characteristic is a compatibility risk for those propagated RPC features; it is not, by itself, proof that ordinary split key input cannot work. Validate boot logs, characteristic subscriptions, position notifications, and RPC behavior as separate gates.
